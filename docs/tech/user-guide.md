# Agent Office — 사용 안내 (MVP · 로컬)

작성일: 2026-10-02
이 문서는 MVP를 직접 써 보고 테스트할 때의 순서예요. 처음에는 가짜 AI와 드라이런(실제로 올리지 않음)으로 시작해서, 하나씩 실제 연결로 바꿔 가요.

## 1. 켜기
```bash
npm install
npm run dev
```
브라우저에서 http://127.0.0.1:4317 을 열어요. 이 컴퓨터에서만 접속돼요.

설치 스크립트로 깔았다면 명령으로 써요(결정 77): `agent-office start`(켜기) · `agent-office demo`(가짜 AI 데모) · `agent-office doctor`(Node · 의존성 · 데이터 폴더 · 포트 · Claude Code 점검) · `agent-office backup`(사무실 데이터를 파일 하나로 — 켜져 있어도 안전) · `agent-office update`. 저장소에서 바로 쓸 때는 `node bin/agent-office.mjs doctor`처럼 실행해요.

## 2. 처음 흐름 — 가짜 AI로 먼저
1. 서비스 소개를 보고 사업을 소개해요(예시: 카페 · 앱 서비스 · 온라인 판매) → “사무실에 전기를 넣어 주세요”에서 **가짜 AI**를 고르고 진행해요.
2. 매니저 후보 3명 중 한 명을 고르고 외형·말투·성향·보고 스타일을 다듬어 계약해요.
3. **사업 인터뷰** — 단계 · 고객 · 막힘 · 이번 달 목표 · 가진 것 · 직접 할 일을 칩이나 직접 입력으로 답해요. 모르면 “잘 모르겠어요”(가정으로 남아요).
4. **사업 설계도** — 매니저가 쓴 요약 · 이번 달 목표 · 업무 블록 · 채용 순서를 보고, 블록을 빼거나 더하고 목표를 고치거나 글로 고쳐 달라고 한 뒤 확정해요.
5. **첫 주 시작** — 매니저 혼자 “사업 진단 · 이번 달 실행 계획”을 써서 **결정함**에 '결과물 확인'으로 올려요. 문단에 코멘트를 달아 수정 요청(이번만/앞으로도)하거나 확정해요.
6. 계획을 확정하면 다음 회차부터 계획의 주차별 블록 + 주간 회고로 일해요. 아직 없는 직무의 블록은 '채용 후 가능' — 회사 › 채용 탭이 설계도의 순서대로 다음 직무를 추천해요.
7. 콘텐츠 운영 블록을 고른 사업만 블로그 · SNS 게시 확인이 와요(처음엔 드라이런 — 예약 시각에 기록만 남아요). 결정 73 이전에 만든 사무실은 지금처럼 콘텐츠 운영으로 돌아요.

## 3. Claude 구독으로 바꾸기
1. 터미널에서 `claude`를 실행해 구독으로 로그인돼 있는지 확인해요.
2. 설정 › 전력실에서 “Claude 구독 (Claude Code)”을 골라요. 상태가 “가동 중”이면 준비 끝.
3. 사용량이 가장 적은 것부터: 매니저 혼자 있는 상태에서 회차를 시작하면 기획 1건만 실행돼요.
4. 실패하면 업무 옆에 CLI 메시지 요약이 남아요(한도 → 한도 대기, 로그인 → 재연결 필요).
- 한 번 실행 비용 상한(API 환산): `.env.local`의 `CLAUDE_MAX_BUDGET_PER_RUN_USD`(기본 $1).
- 화면 없는 상시 VPS 운영은 Anthropic 회신 전까지 하지 않아요(결정 61).

## 4. 앱 연결 — 설정 › 열쇠함
각 앱 태그를 누르면 만드는 방법이 같이 나와요. 비밀값은 암호화해 저장하고 다시 보여주지 않아요.

| 앱 | 준비할 것 | 확인 방법 |
| --- | --- | --- |
| Notion | 내부 통합 토큰, 결과물을 모을 페이지(통합 초대) | 회차 결과물이 그 페이지 아래에 “제목 (v1)”로 생겨요 |
| Google Docs | OAuth 클라이언트(웹 앱, 리디렉션 `http://127.0.0.1:4317/oauth/callback/google`) | “Google로 연결” 후 Drive의 Agent Office 폴더 |
| Slack | 수신 웹훅 주소 | “테스트 알림” |
| Ghost | 사이트 주소, Admin API 키 | 연결 시 사이트 이름 표시 |
| WordPress | 사이트 주소, 사용자 이름, 애플리케이션 비밀번호(HTTPS) | 연결 시 사용자 이름 표시 |
| Threads | 장기 액세스 토큰(본인을 테스터로) | 연결 시 @아이디 표시 |
| LinkedIn | 액세스 토큰(openid·profile·w_member_social), API 버전 | 연결 시 이름 표시 |
| 이미지 생성 | OpenAI API 키(종량제 — 키에 한도를 걸어 두세요) | 이미지 기획 후 썸네일이 결정함 미리보기에 붙어요 |

## 5. 실제 게시 켜기 — 설정 › 결재 규칙
- “실제 게시 켜기”를 누르기 전에는 승인해도 드라이런이에요.
- 처음에는 테스트 블로그·계정으로 시작하길 권해요(게시 테스트 대상은 결정 59에 따라 그때 정해요).
- 결과가 불명확하면(응답 시간 초과·서버 오류) **확인 필요**가 되고 다시 올리지 않아요. 콘텐츠 › 장부에서 “외부에서 확인 · 게시됨” 또는 “게시 안 됨”으로 정리해요.
- 실패한 게시는 같은 승인 버전으로 다시 시도할 수 있어요.

## 6. 매주 자동으로 — 설정 › 건물
주간 회차 예약(요일·시각)을 정하면 그 시각에 회차가 시작돼요. 이 컴퓨터가 켜져 있을 때만 일하고, 꺼져 있던 동안 놓친 예약은 다시 켜질 때 한 번만 실행해요.

## 7. 사무실 공간 — 짓기 · 배치
- **공간 설계:** 사무실 화면의 "공간 설계 부탁하기"를 누르면 매니저가 회사 설명에 맞는 공간(사무실 · 스튜디오 · 연구소 …)을 설계해요. 설계도는 AI가 한 번 써요(구독 사용량 조금).
- **짓기:** 점선 칸(빈 부지)을 누르면 조건 · 비용 · AI 사용량이 보이고, 되면 [짓기]. 비용은 화면 위쪽의 실적 자원(🔎 인사이트 · ✍️ 원고 · 🎨 디자인 · 🤝 신뢰, 직무를 더 뽑으면 📣 홍보 · 🖋️ 교정 · 🎬 영상 · 🔑 키워드)으로 내요. 직원이 끝낸 일에서만 쌓여요.
- **사무실 레벨:** 레벨이 지을 수 있는 방 수를 정해요. 조건을 채우면 매니저가 결정함에 **사무실 레벨 업** 제안을 올려요. 올리면 사무실에서 짐 상자 · 배너 연출이 한 번 나와요.
- **새 방 요청:** 건물 옆 '＋ 새 방 요청' 부지나 왼쪽 아래 버튼 → 필요한 방을 글로 적기(예: 팟캐스트 녹음실). 매니저가 설계하는 동안 그 자리에 공사 가림막이 서고(누르면 진행 상황), 끝나면 건물 오른쪽에 지어진 채로 생겨요. 비용(신뢰 60)은 공사 동안 잡아 두고 완공 때 써요 — 설계가 실패하면 쓰지 않아요.
- **시설 업그레이드:** 회차 보드 · 결재함 · AI 연결 장비 · 지식 책장 · 마일스톤 진열을 누르면 시설 카드가 떠요. Lv2로 올리면 그 화면에 편의 기능이 열려요 — 회차 결과물 내려받기 · 게시 확인 골라서 승인 · AI 사용 기록표 · 회사 지식 내보내기와 점검 목록 · 기록 카드 이미지 저장. 잠긴 기능 자리에서도 바로 올릴 수 있어요.
- **배치 모드:** 왼쪽 아래 "배치 모드" 또는 물건을 0.8초 꾹 누르기 → 끌어서 옮기기, R로 돌리기, "제자리로". 방 밖 · 겹치는 곳 · 문 앞에는 놓을 수 없어요.
- **확대 · 되돌리기:** 직원을 누르면 확대되고, 카드를 닫거나 빈 곳을 누르면 원래 시점으로 돌아가요.
- **미리보기:** `/?space=music#/office`(뮤직 스튜디오) · `?space=lab`(연구소) · `?space=content`(콘텐츠 랩), `/?stage=0#/office` ~ `?stage=4`(단계 레이아웃).

## 8. 알아 두면 좋은 것
- **홈 · 회원가입 · 로그인(결정 74):** 기본(로컬 모드)은 계정 없이 바로 써요 — 홈은 `/home`에서 미리 봐요. 공개 서비스처럼 써 보려면 `npm run demo:accounts` → http://127.0.0.1:4320/ (홈 → 무료로 시작 → 이메일 가입 또는 'Google로 시작하기'(지금은 임시 화면) → 사무실). 지금은 한 서버에 계정 하나만 만들 수 있어요.
- **대표가 들인 시간:** 화면이 보이고 움직임이 있을 때만 영역별로 재요(결정 72). 콘텐츠 › 지표 '내 개입 시간'(이 회차 · 지난 회차 비교), 회사 › 책장·트로피 '대표가 들인 시간'(이번 주 · 지난주 · 최근 6회차), 복귀 요약에서 봐요. 일한 시간이 줄어들수록 '맡겨두면 알아서 돌아가는' 상태예요. 이 컴퓨터에만 저장되고, 무엇을 봤는지는 저장하지 않아요.
- **직원 더 뽑기:** 회사 › 채용에서 리서처 · 작가 · 디자이너 · 마케터 · 편집자 · 영상 PD · SEO 담당을 고를 수 있어요. 매니저 말고는 같은 직무를 여러 명 둘 수 있고, 회차 업무를 돌아가며 나눠 맡아요. 편집자가 있으면 블로그 게시 확인은 교정본으로 올라와요(수정 요청은 원래 작가에게 가요).
- 30분 넘게 비웠다가 들어오면 매니저의 복귀 보고(결정 → 새 결과 → 지켜볼 것 → 그 밖에)가 열리고, "하이라이트 보기"를 누르면 3D 사무실에서 장면마다 그 직원을 비추며 다시 보여 줘요.
- 직원에게 DM으로 “앞으로도 지킬 규칙”을 보내면 배운 것으로 저장돼 다음 업무부터 반영돼요.
- 회사 › 책장에서 배운 것을 회사 지식으로 승격하면 모든 직원의 업무에 반영돼요.
- 데이터는 `data/`에 있어요. 설정 › 창고에서 내보내기(비밀값 제외)를 받을 수 있어요.
