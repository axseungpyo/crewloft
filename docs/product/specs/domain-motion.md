# Agent Office — 도메인 모델과 상태→모션 매핑 (초안)

작성일: 2026-10-01
상태: 기획 제안. M1(데이터 모델)과 M4(사무실) 전에 확정한다. 구현 기술은 정하지 않는다.

## 1. 용어집과 핵심 개체
| 개체 | 의미 | 주요 속성 |
| --- | --- | --- |
| 사무실 (Office) | 소유자 1명의 회사 단위 | 소유자, 실행 환경, 연결, 정책(확인 단위 등) |
| 직원 (Employee) | 상시 소속 AI 직원. 프로젝트와 무관하게 유지 | 이름, 외형·말투, 기본 직책, 역량, 배운 것, AI 연결 |
| 프로젝트 (Project) | 목표와 완료 조건을 가진 일. R0는 "주간 콘텐츠 운영" 1개 | 목표, 브리프, 반복 주기, 결과물 저장 위치 |
| 배치 (Assignment) | 직원 × 프로젝트. TF 내 역할과 접근 범위 | 역할, 담당 범위, 자료 접근 범위, 기간 |
| 회차 (Cycle) | 반복 프로젝트의 한 번 실행(예: 10월 1주차) | 시작 시각, 업무 목록, 상태, 요약 |
| 업무 (Task) | 담당자 1명이 책임지는 작업 단위 | 담당자, 의존 업무, 상태, 대기 이유, 결과물 |
| 인계 (Handoff) | 업무/자료를 다른 직원에게 넘기는 행위 | 보낸 사람, 받는 사람, 자료, 상태(제안/수락/거절) |
| 메시지 (Message) | DM·프로젝트 대화·사용자 DM | 채널, 보낸 사람, 관련 업무/결과물 |
| 결과물 (Artifact) | 조사/기획/블로그/뉴스레터/SNS 글/이미지 | 종류, 버전, 저장 위치 링크 |
| 결정 요청 (Decision) | 사용자 판단이 필요한 항목 | 종류(게시 확인/채용/지식 승격/범위 변경), 확인 대상 스냅샷·버전, 상태 |
| 외부 행동 (External Action) | 앱에 저장·게시·전송 | 앱, 계정, 대상, 승인 버전, 예약 시각, 실행 상태, 결과 URL, 중복 방지 키 |
| 피드백 (Feedback) | 사용자가 결과물/직원에게 준 평가·수정 | 대상, 내용, 반영 여부 |
| 지식 (Knowledge) | 직원이 배운 것 / 회사 지식(후보·확정) | 출처, 적용 범위, 확인 상태, 수정 이력 |
| 연결 (Connection) | 앱·AI 계정 연결 | 종류, 계정, 권한, 상태, 만료일, 사용 한도 |
| 활동 이벤트 (Event) | 위 모든 변화의 시간순 기록. **UI와 모션의 유일한 근거** | 시각, 주체, 종류, 관련 개체 |

원칙: 화면(상세 패널, 활동 기록, 복귀 요약, 사무실 모션)은 모두 같은 이벤트 기록에서 파생한다. 모션만을 위한 상태를 따로 만들지 않는다.

## 3. 직원 활동 → 모션 매핑 — 제안
| 직원 활동(이벤트에서 파생) | 사무실 표현 | 보조 표시(항상 함께) |
| --- | --- | --- |
| 할 일 없음 | 자리에서 쉬는 자세, 가끔 작은 동작 | "대기" |
| 조사 중 | 자리에서 자료 읽기/화면 스크롤 | 업무명 |
| 작성 중 | 타이핑 | 업무명 |
| 이미지 작업 | 태블릿/그리기 동작 | 업무명 |
| 직원 간 DM | 자리에서 말풍선(묶음 개수) | 말풍선 아이콘 + 상대 |
| 인계 | 받는 직원 자리로 걸어가 자료 전달 | "준 → 하나 자료 전달" |
| 검토 중 | 매니저 자리 또는 회의 테이블에서 문서 보기 | "검수 중" |
| 사용자 응답 대기 | 손 들기/알림 아이콘 | 결정함 링크 |
| 한도 대기 | 휴식 자세 + 재개 시각 | "14:00 재개" |
| 재연결 필요 / 실패 | 경고 아이콘, 작업 멈춤 | 원인과 해결 링크 |
| 연결 끊김(서버 상태 미확인) | 전체 화면 정지, 회색 처리 | "마지막 확인 10:42" |

## 4. 모션 연출 규칙 — 제안
- **모션은 이벤트를 꾸밀 뿐 만들지 않는다.** 실제 이벤트 없이 걷기·대화 장면을 재생하지 않는다.
- **직원별 연출 대기열.** 이벤트가 빠르게 이어지면 최소 표시 시간을 지키며 순서대로 재생한다. 대기열이 일정 길이를 넘으면 중간 장면을 건너뛰고 최신 상태로 이동한다(빠르게 감기로 거짓 리듬을 만들지 않음).
- **묶음 표현.** 짧은 시간의 DM 여러 개는 말풍선 하나와 개수로 표시한다.
- **텍스트 상태가 우선.** 모션이 늦거나 생략돼도 상태 문구·아이콘·활동 기록은 즉시 정확하다.
- **동작 줄이기 / 목록 보기**에서도 같은 정보를 정지 자세와 아이콘으로 제공한다.
- 걷기 경로·가림·접지는 `prototype/motion/`의 검증 결과를 재사용하되, 정해진 16초 타임라인이 아니라 이벤트로 구동되는 구조로 바꾼다.

## 5. 사용자 결정 (2026-10-01)
1. **인계·검토는 걸어가기, DM은 말풍선.** 인계는 보낸 직원이 받는 직원 자리로 3~5초 걸어가 자료를 전달한다. 검토 요청은 매니저 자리로 가서 함께 문서를 본다. 잦은 DM은 자리에서 말풍선과 개수로 표시한다. 인계의 걷기 연출은 수락 이벤트와 연결하며, 수락 전에는 "인계 대기"로 표시한다.
2. **복귀 = 텍스트 요약 + 선택형 하이라이트 리플레이.** 기본은 요약(새 결과, 필요한 결정, 멈춘 업무, 한도·재연결). 사용자가 원하면 부재 기간의 주요 장면을 15~30초로 재생한다. 리플레이는 실제 이벤트 기록만 사용하고 각 장면의 실제 시각을 표시한다. 필요한 결정이 있으면 리플레이보다 먼저 보여준다.

## 6. 피드백과 학습 — 사용자 결정 (2026-10-01)
피드백 입력 경로(모두 R0 포함):
- 결과물 인라인 코멘트: 게시 확인 화면·결과함에서 문장/이미지에 직접 남긴다.
- 평가 버튼 + 한 줄 이유: 👍/👎. 회차별 품질 추이 측정에도 사용한다.
- 직원에게 DM: "다음부터 이모지 쓰지 마" 같은 자연어 지시.
- 외부 수정 자동 감지: 사용자가 Notion/Docs/블로그에서 직접 고친 내용을 원본과 비교해 학습 후보로 만든다.

반영 방식: **자동 반영 + 보이고 고칠 수 있게.**
- 직원이 피드백을 재사용 가능한 규칙으로 정리해 다음 업무부터 적용하고 "하나가 배웠어요: 문장을 더 짧게"처럼 알린다.
- 직원 카드의 `배운 것`에서 출처(어떤 피드백·결과물), 적용 시점, 수정·삭제를 제공한다.
- 일회성 지시("이번 글만 짧게")와 지속 규칙을 구분한다. 애매하면 지속 규칙으로 저장하지 않고 직원이 DM으로 확인한다(제안).

안전장치 — 제안:
- 외부 수정 감지에서 만든 규칙은 `추정`으로 표시하고 수정 전후 비교를 근거로 붙인다. 사용자가 확인하거나 같은 패턴이 반복될 때 확정한다.
- 외부 수정 감지는 사용자가 허용한 저장 위치·게시물에만 적용하며, 앱 권한 범위를 넓히지 않는다.
- 여러 직원·브랜드 전체에 적용될 만한 규칙(예: 브랜드 톤)은 회사 지식 승격 후보로 올리고, 기존 승격 절차(사용자 확인)를 따른다.
- 서로 충돌하는 규칙은 자동으로 덮어쓰지 않고 직원이 확인을 요청한다.
- 성장 표시(숙련도·배운 것 수)는 실제 저장된 규칙과 피드백 반영 결과에서만 계산한다.
