# Agent Office — 회사 지식과 프로젝트 기억

> 2026-10-01 통합 메모: 회사 지식 승격은 R0에 포함(결정 36). 직원별 피드백 학습은 [domain-motion.md](domain-motion.md) §6.

상태: 회사 공통 원칙/검토된 교훈 공유, 원본 자료/대화의 프로젝트별 관리는 사용자 확정. 아래 상세 UX와 검토 절차는 기획 제안이다.

## 지식의 구분
| 구분 | 내용 | 기본 활용 범위 |
| --- | --- | --- |
| 회사 공통 지식 | 사업 소개, 브랜드 원칙, 업무 방식, 사용자 선호, 검토된 교훈 | 필요한 업무를 맡은 상시 직원과 TF |
| 프로젝트 지식 | 목표, 조사 원문, 업무 대화, 의사결정, 결과물 | 해당 프로젝트에 참여하고 접근 권한을 가진 직원 |
| 직원 정보 | 직책, 역량, 피드백과 허용된 업무 선호 | 직원 배치와 업무 수행에 활용하며 프로젝트 자료 권한을 대체하지 않음 |

회사 지식은 모든 정보를 하나로 합친 대화 기록이 아니다. 다른 프로젝트의 원문이나 비공개 내용을 공통 교훈에 그대로 복사하지 않는다.

## 공통 지식으로 남기는 흐름 — 제안
1. 프로젝트의 중요한 결정이나 결과가 나오면 담당 직원/매니저가 재사용할 교훈 후보를 정리한다.
2. 후보에 출처 프로젝트, 관련 결과, 제안 이유, 적용할 범위와 작성 시점을 붙인다.
3. 매니저가 중복·충돌·근거 부족·프로젝트 한정 내용을 점검한다.
4. 사용자가 회사 지식으로 저장할 내용을 확인·수정한다. 원칙/브랜드 기준의 변경은 기존 기준과의 차이를 보여준다.
5. 승인된 내용만 회사 공통 지식으로 활용한다. 검토 전 후보를 확정 사실로 사용하지 않는다.

여기서 사용자 확인 단계와 매니저의 세부 검토 역할은 상세 제안이다. 반복적으로 확인 없이 승격할 수 있는 범위는 아직 정하지 않았다.

## 새 TF 시작 시
- 프로젝트 목표와 담당 역할에 필요한 회사 지식을 전달한다.
- 이전 프로젝트의 원본 자료/대화는 자동으로 전체 공유하지 않는다.
- 추가 자료가 필요하면 출처와 필요 이유를 제시하고 해당 자료에 대한 접근 범위를 확인한다.
- 직원이 과거 TF에 참여했다는 이유만으로 새 TF에 이전 프로젝트의 자료를 노출하지 않는다.
- 사용자가 같은 직원을 다시 고용하거나 재배치할 때도 현재 프로젝트의 접근 범위를 적용한다.

## 화면 제안
사무실에 `회사 지식` 공간을 둔다.
- 공통 원칙 / 업무 방식 / 검토된 교훈 / 검토 대기 항목으로 탐색한다.
- 지식 항목을 열면 내용, 출처, 적용 범위, 마지막 확인 시점, 수정 이력을 보여준다.
- 직원 답변이나 결과물에서 어떤 회사 지식을 참고했는지 관련 항목으로 이동할 수 있게 한다.
- 원본 자료의 출처 링크는 접근 권한을 따르고, 권한이 없으면 원문을 노출하지 않는다.

## 수정과 충돌 처리 — 제안
- 사용자가 공통 원칙을 수정하면 새 업무는 최신 내용을 기준으로 한다.
- 이미 진행 중인 업무에 영향을 주는 변경은 매니저가 식별하고 필요한 업무에 반영한다.
- 서로 다른 프로젝트의 교훈이 충돌하면 기존 지식을 자동 덮어쓰지 않는다. 적용 조건을 나누거나 검토를 요청한다.
- 원본이 삭제되거나 접근할 수 없으면 근거 확인 필요 상태를 표시하고 원문이 유지된다고 가정하지 않는다.
- 지식 보존 기간, 삭제/내보내기와 백업 정책은 별도로 결정한다.

## 확인할 성공 기준
- 새 TF가 검토된 공통 원칙을 적용하면서도 다른 프로젝트 원문을 자동으로 받지 않는다.
- 지식 후보와 확정된 회사 지식을 구별할 수 있다.
- 교훈의 출처/적용 범위/수정 이력을 확인하고 잘못된 내용을 고칠 수 있다.
- 일반 직원 정보/선호에 비공개 프로젝트 원문을 섞어 접근 제한을 우회하지 않는다.
