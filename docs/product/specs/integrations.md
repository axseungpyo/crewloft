# Agent Office — Notion / Google Drive·Docs / Slack 연동 기획

> 2026-10-01 통합 메모: 첫 버전은 소유자 1명 사무실(결정 19)이므로 여러 사람이 쓰는 사무실의 권한 모델은 범위 밖. R0에서 Slack은 알림·공유 채널이며 승인은 앱 결정함(결정 32). 게시 플랫폼(Ghost, WordPress, Threads, LinkedIn)은 [publishing.md](publishing.md).

상태: 세 연동 대상과 사용자가 설정 화면에서 연결을 관리하는 방향은 사용자 확정. 아래 상세 기능과 화면 구성은 검토용 제안이며 구현은 시작하지 않았다.

## 범위와 원칙
- 첫 버전에 Notion, Google Drive·Docs, Slack을 모두 지원한다.
- 사용자는 필요한 앱만 연결한다. 세 앱 연결을 가입/사무실 생성의 필수 조건으로 만들지 않는다.
- 같은 직원이 업무에 필요한 여러 앱을 사용할 수 있다. 앱마다 직원을 별도로 고용할 필요는 없다.
- 앱 연결 여부와 프로젝트/직원의 사용 권한은 구분한다.
- 앱 간 결과 전달은 원본 결과물 링크와 버전을 유지한다. 외부 공유 범위를 자동으로 확대하지 않는다.

## 앱별 기본 기능 제안
| 앱 | 가져오는 맥락 | 수행하는 업무 | 확인할 결과 |
| --- | --- | --- | --- |
| Notion | 사용자가 허용한 페이지의 사업 정보·자료 | 지정된 위치에 조사 보고서·기획서·콘텐츠 초안 작성 및 허용된 수정 | 생성/수정한 페이지 링크 |
| Google Drive·Docs | 사용자가 선택하거나 허용한 파일·문서 | 지정된 위치에 Google 문서 및 결과 파일 저장, 허용된 문서 수정 | 문서/파일 링크 |
| Slack | 허용된 채널의 맥락과 명시적인 업무 요청 | 진행 보고·결과 전달 메시지 준비, 사용자 확인 후 전송 | 대상 채널과 실제 전송 메시지 |

모든 메시지나 문서 본문을 사용자 지시로 간주하지 않는다. Slack에서 누가 어떤 방식으로 업무를 요청할 수 있는지 별도로 정하고, 자료 속 지시가 직원 권한이나 목표를 바꾸지 않도록 한다.

## 대표 업무 흐름
예: “시장 조사 내용을 정리하고, 제안서를 만든 뒤 팀에 공유해줘.”
1. 매니저가 목표와 자료/저장 위치/전달 대상을 정리한다.
2. 리서처가 허용된 자료를 읽고 조사 보고서를 Notion의 지정 위치에 저장한다.
3. 기획 담당자가 조사 결과를 인계받아 Google Docs 제안서를 만들고 Drive의 지정 위치에 정리한다.
4. 매니저가 결과 링크와 요약을 포함한 Slack 메시지를 준비한다.
5. 사용자가 대상 채널과 메시지를 확인한 뒤 전송한다.
6. 사무실의 결과함에는 Notion 페이지, Google 문서, Slack 전송 결과가 각각 연결된다.

세 앱을 모두 사용하는 예시일 뿐 필수 경로는 아니다. Notion만 연결했다면 Notion에서 결과물을 완성할 수 있고, Google만 연결했다면 Google 문서를 결과물로 사용할 수 있다. Slack만 연결한 경우에도 메시지 작성/확인/전송 경로를 독립적으로 검증한다.

## 연결 UX
공통 진입점은 `설정 → 연결된 앱`이다. 사용자가 필요할 때 직접 설정하며, 최초 입력 전에 모든 연결을 요구하지 않는다.
1. 앱 목록에서 Notion, Google Drive·Docs, Slack 중 연결할 앱을 선택한다.
2. 해당 서비스의 로그인/권한 확인 절차를 진행한다.
3. 연결한 계정과 실제 허용할 자원(페이지, 파일/폴더, 채널)을 확인한다. 구체적인 선택 방식은 각 제공자의 권한 모델에 맞춰 설계한다.
4. 프로젝트에 사용할 자료와 결과 저장 위치를 지정한다.
5. 연결 상태와 할 수 있는 행동을 요약하고, 직원에게 해당 프로젝트 업무에 필요한 사용 범위를 부여한다. 앱 연결만으로 모든 직원에게 전체 자원 접근을 부여하지 않는다.

### 설정 화면 구성 제안
앱별 카드 또는 행에 앱 이름, 연결 상태, 연결된 계정/워크스페이스와 주요 동작을 표시한다. Google Drive·Docs는 사용자에게 하나의 연결 항목으로 제안하되 실제 읽기/문서 작성/저장에 필요한 권한을 구분해 보여준다.
| 상태 | 기본 동작 |
| --- | --- |
| 연결 안 됨 | 연결하기 |
| 연결됨 | 연결 관리 |
| 추가 권한 필요 | 필요한 권한 확인 |
| 재연결 필요 | 다시 연결 |
| 일시적 오류 | 상태 확인/재시도 |

`연결 관리` 상세에서 연결 계정, 허용된 자원, 결과물 저장 위치, 사용하는 프로젝트/직원, 재연결 및 연결 해제를 확인한다. 제공자가 지원하지 않는 권한 변경을 제품 내 토글로 즉시 수행할 수 있다고 표시하지 않는다.

### 업무 화면과의 연결
- 필요한 앱이 연결되지 않았으면 업무 옆에 “앱 연결 필요”와 “설정에서 연결”을 표시한다.
- 안내를 누르면 동일한 연결된 앱 설정의 해당 앱 항목으로 이동한다. 별도의 중복 연결 마법사를 만들지 않는다.
- 연결 후 원래 업무로 돌아가 준비 상태를 재확인한다. 앱 연결을 마쳤다는 사실을 게시/발송 승인으로 해석하지 않는다.
- 연결 해제 시 영향을 받는 업무/예약을 안내하고 해당 앱의 후속 실행을 대기시킨다. 이미 생성된 외부 문서나 메시지를 삭제하지 않는다.

표시할 상태: 연결 안 됨 / 연결됨 / 추가 권한 필요 / 재연결 필요 / 일시적 오류.
읽기와 저장 권한을 구분하고, 대상 위치에 쓰기 권한이 없으면 저장 가능으로 표시하지 않는다.

## 실행과 사용자 확인
- 사용자가 자동 저장을 허용한 작업 위치의 조사·초안 저장은 합의된 자율 실행 범위에 포함한다. Notion/Drive의 초안은 Agent Office 내부 임시 초안과 다르며, 그 위치의 기존 접근 권한을 가진 사람에게 보일 수 있음을 연결 설정에 표시한다.
- Slack 전송은 외부 발송이므로 기본적으로 사용자 확인을 받는다. 진행 보고라는 이유로 이 정책을 우회하지 않는다.
- 공유 대상 변경, 공개 게시, 링크 접근 범위 확대는 일반 초안 저장과 구분해 확인 대상으로 제안한다.
- 사용자가 메시지/대상/내용을 수정하면 확인할 미리보기도 갱신한다.
- Slack에 링크를 보낼 때 수신자에게 문서 접근 권한이 있는지 알 수 없으면 확인 필요를 표시한다. 접근 가능 여부를 보장하거나 임의로 문서를 공개하지 않는다.

## 업무 기록과 중복 방지 요구사항
각 외부 행동에 앱, 계정, 대상, 관련 업무, 결과물 버전, 확인 상태, 실행 상태 및 결과 링크를 기록한다.
- 문서 생성과 Slack 전송은 별도 행동으로 기록한다.
- 문서 생성은 성공하고 Slack 전송이 실패하면 전송 단계만 복구 대상으로 한다.
- 전송 성공 여부가 불명확하면 무조건 재전송하지 않는다. 외부 결과 확인 또는 사용자 확인이 필요하다.
- 화면을 닫거나 재접속해도 기록과 사용자 확인 상태를 유지한다.
- 연결 해제 후에는 그 앱을 사용하는 후속 업무를 대기시키고, 다른 앱의 독립 업무는 계속할 수 있게 한다.

## 완료 기준 제안
1. Notion만 연결해 허용된 페이지를 읽고 결과 페이지를 저장할 수 있다.
2. Google Drive·Docs만 연결해 허용된 자료를 읽고 문서를 생성/저장할 수 있다.
3. Slack만 연결해 정해진 방식의 요청을 업무로 만들고, 확인 후 결과 메시지를 전송할 수 있다.
4. 세 앱 간 결과물 인계가 원본과 버전을 참조하고 사용자 확인 정책을 유지한다.
5. 권한 없음/만료/연결 해제/일시적 실패가 업무 상태에 정확히 반영된다.
6. 로컬과 VPS에서 지원할 인증 방식과 연결 지속성을 각각 검증한다. 클라우드 앱 연결과 로컬 추론 모델 사용은 서로 다른 조건으로 설명한다.
7. 사용자가 설정의 연결된 앱에서 연결·상태 확인·재연결·해제를 수행할 수 있고, 업무 화면의 연결 안내도 같은 설정 경로를 사용한다.

## 미결정 사항
- 개인용 연결과 여러 사람이 쓰는 사무실의 계정/권한 모델 중 첫 버전의 구체적인 범위.
- Slack 업무 요청을 받을 주체와 방식(지정 사용자 멘션, 특정 채널 등).
- 첫 버전의 문서 서식/첨부파일 처리 범위.
- 앱별 인증/배포 방식과 설치 UX. 공식 문서 확인 후 기술 계획에서 선택한다.

## 공식 문서 확인 — 2026-09-27
아래는 기능/권한 근거이며 구체적인 구현 방식의 확정이 아니다.
- Notion: 연결에 공유되거나 사용자가 선택한 페이지에 대한 접근이 필요하다. 전체 워크스페이스 접근을 전제하지 않는다.
  https://developers.notion.com/guides/get-started/authorization
- Google Docs: 문서 생성과 내용 갱신 API를 제공한다. Drive 파일 선택/저장 흐름에 필요한 권한을 따로 설계한다.
  https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/create
  https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/batchUpdate
- Google: 선택/생성한 파일 중심의 최소 권한으로 요구사항을 충족할 수 있는지 검토한다. 파일 공유 권한 변경은 문서 작성과 별도 행동이다.
  https://developers.google.com/workspace/docs/api/auth
  https://developers.google.com/workspace/drive/api/guides/manage-sharing
- Slack: 채널 기록 접근은 앱의 권한과 채널 참여 범위에 의존하며 메시지 전송 권한은 별도이다. 비공개 채널/DM 전체 접근을 기본으로 요청하지 않는다.
  https://docs.slack.dev/reference/methods/conversations.history/
  https://docs.slack.dev/reference/scopes/chat.write/
- 로컬/VPS: Google의 설치형 앱 인증과 웹/서버형 인증을 구분한다. Notion/Slack 연결의 콜백과 지속 인증 방식은 배포 설계에서 검증한다. 세 제공자가 동일한 로컬 인증 방식을 제공한다고 가정하지 않는다.
  https://developers.google.com/identity/protocols/oauth2/native-app
  https://docs.slack.dev/authentication/installing-with-oauth/
