# 첫 페이지 · 계정 — 온보딩 앞 단계 기획 (결정 74)

2026-10-04 사용자: "온보딩 이전에 웹앱 첫페이지부터 구현하는 기획도 필요해. 메인 홈페이지부터, 로그인 페이지 등등."
사용자 선택: **공개 서비스 기준**(누구나 들어오는 홈 → 회원가입 · 로그인 → 내 사무실, 나중의 상용 서비스(R2)로 갈 구조. 지금 로컬에서는 로그인 없이 바로 쓴다) · 로그인 = **구글 로그인 + 이메일 · 비밀번호**.
> **2026-10-04 결정 77:** 출시는 오픈소스(셀프호스트) 먼저. 이 문서의 홈 · 계정은 서버에 올려 쓰는 사람의 선택 기능(`AUTH_MODE=accounts`)으로 남고, 계정별 사무실(H2) · 실제 구글(H3) · 메일(H4) · 요금(H5)은 관리형 서비스(R2)를 다시 판단할 때까지 미룬다 — [open-source](open-source.md).

관련: [사업 맞춤 셋팅](business-setup.md)(로그인 뒤 온보딩) · [ui-ux](ui-ux.md) · [deployment](deployment.md) · [publishing](publishing.md) §3(R2의 AI 정책).

## 1. 페이지 지도
```
공개(로그인 전)
  /            홈 — 소개 · 어떻게 돌아가나 · 예시 결과물 · 사업 종류별 공간 · 신뢰 · 성장 · 요금 · 자주 묻는 질문
  /signup      회원가입 — 구글로 시작 / 이메일 · 비밀번호
  /login       로그인 — 구글 / 이메일 · 비밀번호 · 비밀번호 찾기
  /forgot      비밀번호 찾기 — 이메일로 재설정 링크
  /reset       새 비밀번호 정하기(메일 링크로 들어옴)
  /verify      이메일 확인(가입 메일 링크로 들어옴)
  /terms · /privacy   이용약관 · 개인정보 처리방침
  (그 밖의 주소)        404 — 홈 · 내 사무실로 가는 길
로그인 뒤
  /app         내 사무실(지금 앱) — 처음이면 온보딩(사업 인터뷰), 아니면 사무실
  /app#/settings/account   계정 — 이메일 · 비밀번호 · 구글 연결 · 로그아웃(모든 기기) · 데이터 내보내기 · 탈퇴
```
- 로그인 상태로 `/`, `/login`, `/signup`에 오면 `/app`으로 보낸다(홈의 '내 사무실 열기' 버튼으로도).
- 로그인 없이 `/app`에 오면 `/login?next=…`로 보내고, 로그인 뒤 원래 가려던 곳으로 돌려보낸다.
- **로컬 모드(지금 · R0):** 계정 없이 한 사람이 쓴다. `/`는 곧바로 `/app`(지금처럼), 홈은 `/home`에서 미리 본다. 외부 접속(VPS)에서는 지금의 소유자 비밀번호를 그대로 쓴다. 설정 하나(`AUTH_MODE=local | accounts`)로 바꾼다.

## 2. 홈 (/)
목표: 처음 온 사람이 **10초 안에 "나 같은 창업 초보에게 AI 팀이 붙는구나"**를 알고, **[무료로 시작]**을 누르게 한다.

| 순서 | 구역 | 내용(초안 문구) |
| --- | --- | --- |
| 1 | 머리글 | 로고 · [어떻게 돌아가나] [요금] [자주 묻는 질문] · [로그인] [무료로 시작] |
| 2 | 첫 화면 | **"창업, 혼자 시작해도 팀이 있어요."** / "하려는 사업을 말해 주세요. 매니저가 사업을 이해하고, AI 팀이 조사 · 계획 · 준비를 나눠 맡아요. 대표님은 확인만 하면 돼요." / [무료로 시작] [3D 사무실 구경하기] — 오른쪽에 살아 움직이는 3D 사무실(견본 공간) |
| 3 | 어떻게 돌아가나 | ① 사업을 설명해요 → ② 매니저가 사업 설계도와 팀을 짜요 → ③ AI 팀이 일하고, 대표님은 확인 · 결정만 |
| 4 | 첫 주에 받는 것 | 사업 진단 + 이번 달 실행 계획 · 고객 인터뷰 질문지 · 준비 체크리스트 — 실제 견본을 카드로(펼쳐 보기) |
| 5 | 사업마다 다른 사무실 | 카페 · 앱 서비스 · 온라인 판매 · 크리에이터 탭 — 탭마다 3D 공간 견본(필요의 방) |
| 6 | 믿고 맡길 수 있게 | 밖으로 나가는 일(게시 · 발송 · 결제)은 대표 확인 뒤에만 · 모르는 건 '가정'으로 표시 · 법 · 세무는 '전문가 확인 필요' · 내 데이터는 내보내기 · 삭제 가능 |
| 7 | 함께 자라는 사무실 | 일할수록 사무실이 커지고, 직원이 배우고, 대표님이 들인 시간은 줄어요 — 레벨 · 성적표 화면 예시 |
| 8 | 요금 | 미정 — 무료 체험 + 플랜(가정). R2의 AI 비용 구조가 정해져야 확정(아래 7) |
| 9 | 자주 묻는 질문 | AI는 무엇을 쓰나요 · 비용은 · 제 사업도 되나요 · 데이터는 안전한가요 · 언제든 그만둘 수 있나요 |
| 10 | 마지막 권유 · 바닥글 | [무료로 시작] / 약관 · 개인정보 · 문의 |

- 3D는 무겁다 — 첫 화면은 정지 그림을 먼저 보여 주고 3D는 화면에 들어오면 불러온다. WebGL이 없으면 그림만.
- 휴대폰: 구역을 한 줄로, 3D 대신 짧은 영상 · 그림.

## 3. 회원가입 · 로그인
**회원가입 (/signup)**
- [Google로 시작하기] — 첫 줄, 가장 크게.
- 또는 이메일 · 비밀번호(8자 이상, 보이기 버튼) · 이용약관 · 개인정보 동의(필수 체크 하나) → [가입하기].
- 가입 뒤 확인 메일을 보내고, 확인 전에도 바로 온보딩을 시작할 수 있다(확인은 외부 연결 · 게시 전에 요구).
- 이미 가입한 이메일이면 "이미 가입된 이메일이에요 — 로그인할까요?"(구글로 가입한 이메일이면 "Google로 로그인해 주세요").

**로그인 (/login)**
- [Google로 계속하기] / 이메일 · 비밀번호 / [로그인] / 비밀번호 찾기 · 회원가입 링크.
- 틀리면 "이메일 또는 비밀번호가 맞지 않아요"(어느 쪽이 틀렸는지 말하지 않음). 5번 넘게 틀리면 잠깐 막는다.
- '로그인 유지'(30일) 기본 켬.

**비밀번호 찾기 · 재설정 · 이메일 확인**
- 찾기: 이메일 입력 → 가입 여부와 상관없이 "메일을 보냈어요(가입된 이메일이면 도착해요)". 링크는 30분 · 한 번만.
- 재설정: 새 비밀번호 두 번 → 다른 기기 로그인은 모두 끊는다.
- 확인: 링크를 누르면 "이메일을 확인했어요" → 내 사무실.

**구글 로그인** — OpenID Connect(인가 코드 + PKCE · state). 이메일 · 이름 · 사진만 받는다. 같은 이메일의 이메일 계정이 있으면 확인 후 연결.

## 4. 계정 · 데이터
- **계정마다 사무실 하나**(한 명이 쓰는 사무실 — 여러 사람이 함께 쓰는 사무실은 계속 범위 밖).
- 데이터 분리(제안): 계정마다 따로 저장(지금 구조를 그대로 쓰는 계정별 데이터 파일). 공용 '계정 저장소'에는 계정 · 세션 · 로그인 기록만.
- 비밀번호는 지금처럼 scrypt로만 저장, 세션은 지금처럼 쿠키(HttpOnly · SameSite=Lax · 공개 서비스에서는 Secure).
- 계정 화면: 이메일 · 비밀번호 바꾸기 · 구글 연결/해제 · 모든 기기 로그아웃 · 데이터 내보내기(지금 있는 내보내기) · 탈퇴(사무실 데이터 삭제 확인 두 번).
- 메일 보내기: 가입 확인 · 비밀번호 재설정 두 가지. 보낼 서비스는 미정(로컬 개발에서는 메일 대신 화면 · 기록에 링크를 남긴다).

## 5. 로그인 뒤 연결
- 처음 로그인 → `/app` → 온보딩([사업 맞춤 셋팅](business-setup.md))의 1단계 '서비스 소개'는 홈을 보고 온 사람에겐 짧게(이미 본 내용 건너뛰기), 바로 가입한 사람에겐 그대로.
- 대표가 들인 시간(결정 72)은 계정마다 따로 잰다.

## 8. 구현 단계(제안)
| 단계 | 내용 |
| --- | --- |
| H1 화면 | 홈 · 로그인 · 회원가입 · 비밀번호 찾기/재설정 · 이메일 확인 · 약관 · 404 화면과 이동 흐름(시안 → 확정 → 구현). 로컬 모드 `/home` 미리보기 |
| H2 계정 | 이메일 · 비밀번호 가입 · 로그인 · 세션 · 계정별 데이터 분리 · 계정 화면 · 로그인 시도 제한 |
| H3 구글 로그인 | OpenID Connect · 계정 연결 |
| H4 메일 | 가입 확인 · 비밀번호 재설정 메일(서비스 정해진 뒤, 그 전엔 로컬 기록) |
| H5 요금 | 요금 정책이 정해진 뒤 |

순서 제안: **H1 시안 → H1 구현과 사업 맞춤 셋팅 P1을 함께** → H2 → H3 → P2 … (계정이 있어야 공개 서비스가 되지만, 제품 핵심 검증(P1)은 로컬 모드로 먼저 할 수 있다.)

## 구현 현황 (2026-10-04)
- **H1 화면 — 됨:** 홈(첫 화면에 살아 움직이는 3D 사무실 · 사업 종류 탭, 어떻게 돌아가나, 첫 주 결과물 견본 3장, 믿고 맡길 수 있게, 함께 자라는 사무실, 요금(준비 중), 자주 묻는 질문), 회원가입, 로그인, 비밀번호 찾기 · 재설정, 이메일 확인, 이용약관 · 개인정보(초안), 404. 코드: `web/site.html`, `web/js/site/*`, `web/css/site.css`.
- **H2 계정 — 일부:** 이메일 · 비밀번호 가입 · 로그인(scrypt, 쿠키 세션 30일), 5번 틀리면 10분 막기, 재설정 시 다른 기기 로그아웃, 설정 화면의 계정 카드(로그아웃 · 모든 기기 로그아웃). **계정별 사무실 분리는 아직** — 그 전까지 한 서버에 계정 하나만 만들 수 있다. 저장: 스키마 v6(`accounts` · `auth_tokens` · `sessions.account_id`), 코드 `src/server/accounts.ts` · `routes-account.ts`.
- **H3 구글 — 임시(사용자 요청 "구글 로그인도 임시로만"):** [Google로 시작하기] → `/auth/google` 임시 계정 선택 화면(이메일 · 이름만, Google에 아무것도 보내지 않음) → 계정 만들거나 연결 → `/app`. `GOOGLE_CLIENT_ID`가 생기면 실제 OpenID Connect로 바꾼다. 운영 환경(`NODE_ENV=production`)에서는 임시 화면이 꺼진다.
- **H4 메일 — 개발용:** 메일 대신 서버 기록과 화면(개발 환경)에 링크를 남긴다.
- **켜는 법:** `AUTH_MODE=accounts`(예: `npm run demo:accounts` → http://127.0.0.1:4320/). 기본(로컬 모드)은 지금처럼 `/`가 곧바로 사무실이고, 홈 · 로그인 화면은 `/home` · `/login`에서 미리보기(로컬 모드 안내 띠, 양식은 꺼짐).
- 서비스 이름 · 주소는 사용자가 추후 결정 — 화면에는 'Agent Office(가칭)'.

## 9. 완료 기준(H1–H4)
1. 처음 온 사람이 홈 → 회원가입(구글 또는 이메일) → 온보딩까지 막힘 없이 간다.
2. 로그아웃 → 로그인 → 하던 사무실 그대로. 다른 계정의 데이터는 보이지 않는다.
3. 비밀번호를 잊어도 메일로 되찾을 수 있다. 틀린 로그인이 이어지면 막힌다.
4. 로컬 모드에서는 지금처럼 로그인 없이 바로 쓴다.
5. 세 화면 폭에서 겹침 · 잘림이 없다.
