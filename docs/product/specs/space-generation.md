# 도메인 맞춤 공간 생성 — '필요의 방' (진행 중)

2026-10-03 사용자 방향: 사용자 도메인은 무궁무진하다. R&D 하는 사람에게는 '연구소'가, 음악 하는 사람에게는 '뮤직 스튜디오'가 필요하다. office라는 틀에 공간을 가둘 필요가 없다. **사용자 도메인에 맞춘 공간 생성이 원칙**이고, 해리포터의 '필요의 방'처럼 필요에 맞춘 공간이 생겨야 한다. 게임처럼 미리 만들어 두고 단계별로 주면 이 제품의 장점이 사라진다. 비용과 건축 시간도 다시 생각한다.

## 원칙 (제안 — 스파이크 후 확정)
1. **모습은 무한히, 뜻은 고정.** 제품 기능과 이어진 자리(회차 보드 · 결재함 · AI 연결 · 회사 지식 · 마일스톤 · 간판)는 어떤 공간에나 있고, 모습만 도메인에 맞게 바뀐다.
   - 예: 뮤직 스튜디오 — 트랙 보드 · 믹싱 콘솔 위 확인 대기 · 앰프 랙 · 레코드 선반 · 골드 레코드 액자
   - 예: 연구소 — 실험 일정판 · 연구 책임자 승인함 · 계산 서버 · 실험 노트 보관함 · 특허·논문 액자
2. **AI가 설계도를 쓰고, 엔진이 조립한다.** 매니저(AI)가 회사 설명 · 팀 · 실제 업무를 보고 공간 설계도(방 · 작업 자리 · 기능 자리의 모습 · 분위기)를 쓴다. 배치 · 통로 · 카메라는 엔진이 자동으로 맞춘다. 없는 소품은 AI가 기본 도형 조합 레시피로 만든다. 지은 공간은 저장되고, 말로 고칠 수 있다.
3. **공간이 생기는 계기는 레벨이 아니라 필요.** 새 직무 채용 · 반복되는 일 · 자리 부족 같은 실제 필요가 생기면 매니저가 공간을 제안하고 대표가 결정한다. 규모 성장(방 → 여러 방 → 층 → 건물 → 캠퍼스)은 성장 재미로 남되, 어떤 방이 생길지는 도메인이 정한다.
4. **비용 · 건축 시간(결정 68):** 비용은 직무별 실적 자원(실제로 끝낸 일에서만 쌓이고 지을 때 씀), AI 사용량은 따로 표시. 이미 설계된 것은 바로 지어진다.

## 스파이크 — 세 도메인을 설계도로 짓기
- 대상: 콘텐츠 사무실 · 뮤직 스튜디오 · 연구소
- 설계도 형식(스키마), 설계도 → 3D 조립 엔진, AI 레시피 소품, 기능 자리 6종의 도메인별 모습
- 확인은 가짜 AI로만 한다. 설계도 견본은 AI가 쓸 출력의 예시다. 실제 AI(구독)로 설계도를 쓰게 하는 길은 열어 두고, 품질은 사용자가 직접 시험한다.
- 판단 기준: 도메인다움이 느껴지는가 · 기능 자리를 바로 알아보는가 · 깨짐(겹침·끼임) 없이 지어지는가 · 레시피 소품의 품질

## 스파이크 결과 (2026-10-03)
**만든 것:** `web/js/office3d/space/`
- `generate.js` — 설계도 다듬기(빠진 기능 자리 보충 · 범위 밖 값 자르기 · 메모) → 방 크기 계산 → 두 줄 + 복도 배치 → 통로 · 카메라 자동

- 견본 설계도 3개: 뮤직 스튜디오(`?space=music`) · 연구소(`?space=lab`) · 콘텐츠 랩(`?space=content`)

**확인된 것**
- 회사 설명이 다른 세 도메인이 같은 엔진으로 지어지고, 직원 · 이름표 · 걷기 · 클릭 · 기능 자리 연결이 그대로 동작한다.
- 레시피 소품(드럼 · 마이크 스탠드 · 앰프 · 턴테이블 · 현미경 · 흄후드 · 원심분리기 · 시약 냉장고 · 삼각대 · 링라이트)이 중간 거리에서 알아볼 만하다.
- 엔진이 배치를 맡아서 겹침 · 끼임이 생기지 않는다(테스트).

**한계**
- 견본은 사람이 쓴 것이다 — 실제 AI가 이 형식을 얼마나 잘 쓰는지는 아직 모른다(사용자 시험 몫).
- 배치가 두 줄 + 복도의 격자라 공간이 다소 평면도 같다. 방 모양 · 동선의 다양성은 다음 과제.
- 레시피 소품은 가까이서 보면 각진 도형이다. 품질을 높이려면 부품 종류(곡면 · 압출) 추가가 필요하다.

**비용 · 시간 추정(설계도 1회 작성 기준)**
| 견본 | 설계도 크기 | 출력 토큰(추정) | 레시피 |
|---|---|---|---|
| 콘텐츠 랩 | 2.5KB | 약 1,000 | 3개 · 17조각 |
| 연구소 | 4.2KB | 약 1,600 | 5개 · 41조각 |
| 뮤직 스튜디오 | 5.1KB | 약 2,000 | 7개 · 51조각 |
- AI 한 번에 설계도 + 레시피를 다 쓴다. 회사 설명 · 팀 · 업무 입력까지 합쳐도 구독 사용량은 보통 회차 업무 하나보다 작다. 실제 시간은 수십 초~1분대로 예상된다(실측은 사용자 시험 때).
- 짓기(조립)는 브라우저에서 즉시 — 비용 0.
- 한 번 쓴 레시피는 저장해 다시 쓰므로, 같은 도메인의 두 번째 공간부터는 더 싸다.

## 짓기 · 배치 (결정 68)
- **사무실 레벨 = 성.** 레벨별 지을 수 있는 방 수(임시): 0→3 · 1→4 · 2→5 · 3→6 · 4→8. 레벨은 이사 제안(결정 66)으로 오른다.
- **처음 공간:** 기능 자리가 있는 방 + 지금 직원이 있는 방은 지어진 채로. 자리는 직무마다 하나(직원이 더 있으면 그만큼). 나머지는 빈 부지.
- **빈 부지 3종:** 방(조건: 레벨 · 그 방 직무 채용, 비용: 신뢰 40 + 방 직무 자원 30) · 자리(그 직무 자원 20 + 신뢰 10) · 꾸미기(디자인 10, 화분 · 조명 · 안락의자 · 책장 · 커피 바, 방마다 2개).
- **실적 자원:** 직원이 끝낸 업무 1건 = 그 직무 자원 10, 승인한 결정 1건 = 신뢰 3. 번 것은 기록에서 계산하고 쓴 것은 `builds` 표(스키마 v4)에 남는다.
- **임시 자리:** 입구 쪽 4자리 — 지은 자리보다 직원이 많으면 여기 앉는다.
- **배치 모드:** 끌어서 옮기기(0.25m 칸) · R 회전 · 제자리로. 방 밖 · 다른 물건과 겹침 · 문 앞은 빨강으로 표시되고 놓이지 않는다. 위치는 `space.placements`에 저장.
- **꾹 누르기(사용자 제안):** 배치 모드 버튼과 함께, 물건을 0.8초 누르고 있으면 배치 모드로 들어가며 그 물건을 바로 끈다. 누르는 동안 원이 차오르고, 움직이거나 일찍 떼면 취소. 2026-10-04 사용자 피드백("캐릭터를 클릭했을 때는 로딩창이 안 나오게, 필요 없잖아"): **직원(캐릭터)을 누르면 꾹 누르기를 하지 않고 카드만 연다**(책상째 옮기려면 책상을 꾹 누르거나 배치 모드). 물건도 원은 0.22초 넘게 누르고 있을 때부터 보여 그냥 클릭엔 나타나지 않는다(`RING_DELAY`). 사용자는 2초 이상을 제안했으나 너무 길어 0.8초로 시작 — `LONG_PRESS_MS` 하나로 바꿀 수 있다.
- **확대 후 되돌리기(사용자 제안):** 직원을 눌러 확대하기 전 카메라 · 층을 기억했다가, 카드를 닫거나 빈 곳을 누르면 그 시점으로 부드럽게 돌아간다.
- **걷기:** 바닥 칸(0.25m) A* — 물건 · 벽을 피해 걷는다. 물건을 옮기면 다시 계산한다.
- 기능 시설 업그레이드는 아래(결정 70).

- **조건:** 사무실 레벨 1 이상. 레벨은 `space.facilities`, 쓴 자원은 짓기 기록(`builds`, kind `facility`).
- **3D:** 시설을 누르면 시설 카드(레벨 · 열린 기능 · 다음 레벨 · 업그레이드 · 그 화면 열기). Lv2 이상이면 시설 위에 금색 'Lv 2' 표(AO 패스에서는 빼서 그림자 판이 생기지 않게).

- **고친 것:** `/api/decisions/batch`가 `/api/decisions/:id`에 먼저 잡혀 주간 묶음 승인이 동작하지 않던 MVP 버그 — 라우터가 고정 경로를 먼저 찾게 했다(테스트).
- **아직:** Lv3 이후 · 시설 모습이 레벨에 따라 커지는 연출.

## 새 방 요청 (결정 69, 2026-10-04)
- **요청:** 건물 옆 '＋ 새 방 요청' 부지나 아래 버튼을 누르고, 필요한 방을 글로 적는다(예시 칩: 팟캐스트 녹음실 · 손님 맞는 회의실 · 쉬는 라운지 · 촬영 스튜디오 · 자료실).
- **조건:** 사무실 레벨의 방 수(공사 중인 방 포함) · 매니저 채용 · 공사 중인 곳이 없을 것. **비용:** 신뢰 60(임시값).
- **공사 = 설계 시간:** 매니저(AI)가 방 하나를 설계하는 동안 다음 자리에 줄무늬 가림막 · 원뿔 · 자재 더미가 선다. 누르면 무엇을 짓는지 · 몇 분째인지 · 잡아 둔 자원이 보인다. 끝나면 그 방이 지어진 채로 생기고 카메라가 그 방을 비춘다.
- **자원:** 공사 동안은 '잡아 둔 자원'으로 빠지고(쓴 것 아님), 완공 때 짓기 기록(`builds`, kind `room_new`)으로 쓴다. 설계가 실패하면 잡아 둔 것이 풀린다 — 상태는 AI 요청 기록에서 읽어서 서버가 다시 켜져도 묶이지 않는다.
- **배치:** 새 방은 `added: true`로 설계도에 붙고, 엔진은 원래 방 배치를 그대로 둔 채 건물 오른쪽에 뒷줄 · 앞줄을 번갈아 붙인다(별관). 있던 방 좌표가 안 바뀌므로 배치 모드에서 옮긴 물건도 제자리다(테스트).
- **설계 규칙(AI):** 방 하나, 기능 자리 없음, 작업 자리 한 줄(최대 3자리), 소품 6개 이하. 이미 있는 레시피 이름은 다시 쓰고(덮어쓰지 않음), 새 소품은 레시피로 만든다. 서버가 id 겹침 · 범위를 다듬는다(`tidyRoom`).
- **막힌 벽:** 카메라 쪽(앞 · 오른쪽) 벽은 1m 남짓으로 잘라 방 안이 보이게 했다.
- **아직:** 매니저가 먼저 필요를 알아채 제안하기(원칙 3) · 지은 방 고치기/허물기.

## 이미 만든 것의 자리
3D 엔진 · 캐릭터 · 걷기 · 이름표 · 기능 자리 연결 · 이사 제안 흐름은 그대로 쓴다. 0–4단계 레이아웃(결정 66)은 '미리 정한 단계'가 아니라 설계도 예시 · 기본값이 된다.
