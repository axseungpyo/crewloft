# Agent Office — 실행 환경과 운영 경험

> 2026-10-01 통합 메모: 세 실행 환경은 R0(로컬 개발 + 본인 VPS) → R1(오픈소스 셀프호스트) → R2(관리형 SaaS) 순서로 제공(결정 24·26). 아래 "관리형 기본 추천"은 R2 기준 제안이다. "서비스 제공 AI 기본"은 결정 25로 대체됐다.

상태: 로컬, 개인 VPS, 서비스 관리형 서버 지원은 사용자 확정. 아래 상세 UX와 운영 규칙은 기획 제안이다. 서버 구축/배포는 수행하지 않았다.

## 지원 범위
| 방식 | 실행 장소 | 인프라 운영 책임 | 사용자 경험의 목표 |
| --- | --- | --- | --- |
| 로컬 | 사용자의 컴퓨터 | 사용자 | 내 컴퓨터에서 사무실을 실행하고 관리 |
| 개인 VPS | 사용자가 준비한 서버 | 사용자, 제품은 설치/진단 도구 제공 | 서버를 연결해 내 컴퓨터를 꺼도 업무 지속 |
| 관리형 | 서비스가 제공하는 서버 | 서비스 운영자 | 서버를 직접 설치하지 않고 사무실 이용 |

세 방식 모두 첫 버전 지원 대상으로 유지한다. 운영 방식에 따라 같은 앱 연결/직원/업무 기능을 사용할 수 있게 하되 지원 조건과 제한은 실제 환경에 맞게 표시한다. 관리형의 무료/유료 여부, 용량과 요금은 아직 정하지 않는다.

## 최초 시작 경험 — 제안
- 일반 사용자에게 관리형을 기본 추천하되 로컬과 개인 VPS도 선택할 수 있게 한다. 이 기본 추천 순서는 아직 사용자 결정이 아니다.
- 사업 설명과 팀 제안을 작성하는 동안 실행 환경의 모든 세부 설정을 요구하지 않는다.
- 실제 직원 업무를 시작하기 전에는 선택한 실행 장소, 필요한 앱 연결, 비용 정책의 준비 상태를 확인한다.
- 관리형: 사무실 생성 → 필요한 앱 연결 → 합의한 팀으로 시작.
- 로컬: 실행 프로그램 준비/상태 확인 → 사무실 연결 → 필요한 앱 연결 → 시작.
- 개인 VPS: 서버 준비 → 설치/연결 안내 → 연결 상태 확인 → 필요한 앱 연결 → 시작.

로컬 실행 프로그램의 패키징, VPS 설치 명령, 지원 OS/서버 사양, 관리형 리전 등은 기술 계획에서 검증하고 정한다.

## 설정 → 실행 환경
설정의 연결된 앱 메뉴와 별도로 실행 환경 메뉴를 둔다.
표시 항목:
- 현재 실행 방식과 기기/서버 이름.
- 연결 상태와 마지막 확인 시각.
- 실행 중/대기 중 업무, 사용자가 정한 실행 제한.
- 해당 환경에서 사용할 수 있는 앱 연결 상태.
- 연결 관리, 재연결, 일시정지, 실행 장소 변경 진입점.

앱 계정 연결과 서버 연결은 다른 설정이다. 서버 연결 성공을 Notion/Google/Slack 연결 성공으로 표시하지 않는다.

## 공통 동작 요구사항 — 제안
- 사무실을 보는 화면과 업무를 실행하는 환경을 구분한다.
- 개인 VPS/관리형에서는 사용자 화면을 닫아도 허용된 업무가 계속된다.
- 로컬은 해당 기기의 실행 상태에 의존한다. 절전/종료 중에도 업무가 진행된다고 안내하지 않는다.
- 연결이 끊기면 확인 가능한 마지막 상태를 보여주고, 정상 작동 모션을 계속 재생하지 않는다.
- 외부 게시/발송/결제/추가 고용에 대한 사용자 확인 정책은 세 환경에 동일하게 적용한다.
- 한 업무를 여러 환경이 동시에 중복 수행하지 않도록 책임 실행 환경을 명확히 기록한다.
- 최초 버전에서 직원별로 로컬/VPS/관리형을 섞는 분산 배치는 필수로 확정하지 않는다. 기본안은 사무실 단위의 하나의 실행 환경이다.

## 데이터와 연결 정보 — 제안
- 사용자가 작업 기록/결과물/앱 연결 정보가 어디에 저장되는지 확인할 수 있게 한다.
- 관리형은 사용자의 사무실과 연결 자원을 구분해 운영하고, 연결 해제와 데이터 보존/삭제 정책을 제공해야 한다.
- 로컬/개인 VPS 지원을 완전한 오프라인 운영과 동일시하지 않는다. 연결 앱과 선택한 AI 이용 방식에 따라 외부 통신이 필요하다.
- 실행 장소 변경 시 기존 기록, 진행 업무, 앱 연결 중 무엇이 이동하고 무엇이 재설정되는지 미리 보여준다.
- 서버 간 무중단 이전, 자동 비밀정보 복사, 양방향 동기화는 이번 합의만으로 약속하지 않는다. 전환/이전의 상세 범위는 별도 결정이다.

## 관리형 운영에 추가로 필요한 기획
- 사용자 계정/사무실별 데이터와 앱 연결의 접근 범위.
- 서버 및 AI 사용량 제한, 비용 표시와 과금 단위.
- 작업 실패/재시작/연결 만료 시 사용자 안내.
- 기록 보존, 백업/복구, 탈퇴/데이터 내보내기 정책.
- 장애 안내와 운영 지원 범위.

이 항목들은 관리형을 실제 제품으로 제공하기 위한 계획 대상이다. 현재 완료됐다는 의미가 아니다.

## 검증 기준 제안
1. 같은 기본 업무 흐름을 로컬, 개인 VPS, 관리형 각각에서 완료할 수 있다.
2. 개인 VPS/관리형에서 화면을 닫아도 실행 이력이 유지되고 재접속 시 결과를 볼 수 있다.
3. 로컬 중지/서버 연결 장애를 정상 실행으로 표시하지 않는다.
4. 실행 환경을 다시 연결했을 때 외부 저장/전송을 중복 수행하지 않는다.
5. 앱 연결 상태와 실행 환경 상태를 각각 확인하고 복구할 수 있다.
6. 세 환경에서 동일한 사용자 확인 경계가 적용된다.

## 후속 AI 제공 결정
사용자는 서비스 제공 AI를 기본으로 하고 개인 구독 및 API 키 연결을 지원하는 방향을 선택했다. `ai-connections.md`에 상세를 기록한다. 서버 이용료와 AI 사용료는 별도 항목으로 구분하며, 구독 제공자별 관리형 환경 지원 조건은 별도로 검증한다.
