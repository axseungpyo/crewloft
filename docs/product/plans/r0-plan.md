# Agent Office — R0 개인 검증판 계획 (초안)

작성일: 2026-10-01
상태: 마일스톤 순서(M0–M6)와 R0 제외 항목은 2026-10-01 사용자 확정. 근거 결정: product-draft 19–36.

## R0 한 줄 정의
본인 1명이 자기 VPS에서 한 명씩 채용한 AI 팀(매니저부터, 로드맵 예시 4인)에게 **주간 콘텐츠 운영**(조사 → 기획 → 블로그·뉴스레터·SNS 글·이미지 → 확인 → Ghost/WordPress/Threads/LinkedIn 게시)을 맡기고, 2D 사무실에서 과정을 보며, 피드백할수록 팀이 나아지는 것을 확인한다.

## 고정된 전제
- 사용자: 본인 1명, 소유자 1명 사무실.
- AI: 로컬은 Claude 구독(공식 Claude Code CLI 헤드리스 호출, 결정 61)을 먼저 붙였고 Codex는 후속. 무인 VPS의 Claude 사용은 Anthropic 문의 결과에 따름. 한도 도달 시 업무 중단(대기), 자동 전환·과금 없음.
- 앱: Notion, Google Drive·Docs, Slack(알림), Ghost, WordPress, Threads, LinkedIn.
- 실행: 로컬 개발 → 본인 VPS 상시 운영.
- 게시: 기본 게시물별 확인, 설정으로 주간 패키지/플랫폼 사전 허용 선택. 알림 Slack, 승인 앱 결정함.
- 통과 게이트: 기능 완성 → 3주 연속 실운영 → 주변 사용자 테스트.

## R0 범위 경계 — 사용자 확정
R0에서 제외(후속): 여러 프로젝트 TF 동시 운영과 배치 조정. R0는 한 명씩 채용한 상시 팀(로드맵 예시 4인) + 주간 콘텐츠 프로젝트 1개로 검증한다.

R0에 포함(사용자가 제외하지 않음): 로컬 ↔ VPS 실행 장소 전환, 직원별 AI 연결 지정, 회사 지식 승격 절차(주간 회차에서 나온 교훈을 회사 지식으로 확인·저장).

이전 결정으로 이미 R0 밖인 항목: 여러 사람이 쓰는 사무실, 관리형 서버(R2), 서비스 제공 AI, Instagram, X, 뉴스레터 발송, LinkedIn 회사 페이지. (사무실 공간 확장은 결정 66으로 포함으로 바뀜, 그룹(계열사)은 로드맵)

## 기획 개정 — 사업 맞춤 셋팅 (2026-10-04, 결정 73)
- 대상을 '창업을 막 시작하는 사람(사업 종류 무관)'으로, 업무를 '콘텐츠 운영 고정' → '업무 블록 조합'으로, 첫 결과물을 '사업 진단 + 이번 달 실행 계획'으로 바꾼다.
- 구현: P1 온보딩 · 첫 결과물 → P2 업무 블록 엔진 → P3 직무 · 채용 → P4 기준 · 검증. 상세: [business-setup](../specs/business-setup.md).
- R0 통과 게이트(기능 완성 → 3주 실운영 → 주변 사용자 테스트)는 그대로, '기능 완성'의 기준을 P4에서 개정한다.
- **온보딩 앞 단계(결정 74):** 홈 · 회원가입 · 로그인 · 비밀번호 찾기 · 약관 · 계정 — 공개 서비스 기준, 구글 + 이메일 · 비밀번호. 순서: H1 화면(시안 → 구현, P1과 함께) → H2 계정 → H3 구글 → H4 메일 → H5 요금. 상세: [entry-pages](../specs/entry-pages.md).
