## 1. MVP 정의
PRD §12의 R0 기능 완성 기준을 **로컬 실행**으로 충족하는 제품. 화면은 채택한 S1–S8과 S3 채용 흐름을 따르고, AI는 Claude 구독(Claude Code CLI)과 가짜 AI로 동작한다.

| PRD §12 기준 | MVP에서 |
| --- | --- |
| 1. 빈 상태 → 질문·브리프 → 채용 | S3: 사업 소개 → AI 연결 → 매니저 면접(AI 진단) → 다듬기·계약 → 기획 회의 → 한 명씩 채용 |
| 2. 수락 기반 인계가 대화·업무·모션에서 같게 보임 | 기본 시스템 + S1 사무실(이벤트로만 움직임) + 직원 카드 |
| 3. Notion/Docs 저장 + 4개 플랫폼 게시, 승인 버전만 | 연동 7종(아래) + 게시 예약 실행기 + 버전 스냅샷 |
| 4. 불명확한 게시는 재실행하지 않고 `확인 필요` | 게시 결과 확인 절차 + S5 상태별 행동 |
| 5. 화면을 닫아도 예약 회차 완료 + 복귀 요약·리플레이 | 예약 회차·예약 게시 + S6 (VPS 구축은 설계만 — 결정 60) |
| 6. 한도·토큰 만료·연결 해제가 해당 업무에만 반영 | 기본 시스템 + 연결별 상태 + 재연결 결정 요청 |
| 7. 피드백이 배운 것으로 보이고 다음 회차에 반영 | 피드백 → 배운 것(이번만/앞으로도) → 프롬프트 반영 + S4 |

## 2. 범위
**포함**
- 화면: S1 사무실 · S2 결정함(모바일 포함) · S3 채용 · S4 직원 · S5 콘텐츠 · S6 복귀 요약 · S7 설정 · S8 회사.
- 연동: Notion(내부 통합 토큰), Google Docs(OAuth 설치형 앱, 루프백), Slack(수신 웹훅), Ghost(Admin API 키), WordPress(애플리케이션 비밀번호), Threads(액세스 토큰), LinkedIn(액세스 토큰), 이미지 생성(OpenAI 이미지 API 키, 선택).
- 학습·성장: 피드백(문단 코멘트·평가·수정 요청·DM) → 배운 것, 회사 지식 승격, 기록 기반 숙련도, 마일스톤, 승급 제안.
- 운영: 주간 예약, 게시 예약, 알림, 소유자 비밀번호(외부 접속 시), 실행 장소 잠금.

**제외(MVP 이후)**
- VPS 실제 구축, Codex·Gemini 연결, 최종 일러스트 자산(아트 디렉션 확정), 외부 수정 자동 감지, 여러 TF, 앱 OAuth 앱 심사가 필요한 흐름(LinkedIn·Threads는 토큰 붙여넣기로 시작).

## 3. 임시 기본값 — 사용자 미결정 사항
MVP를 막지 않도록 기본값을 두고, 설정에서 바꿀 수 있게 한다.

| 항목 | 기본값 |
| --- | --- |
| 알림 빈도(우편함) | 결정 요청·재연결·실패는 바로 Slack 알림, 같은 종류는 10분 안에 묶음. 회차 마무리 요약 1회 |
| 직급 기준(결정 57) | 실장: 최근 4회차 연속 '경미 수정 이하 채택률' 75% 이상 → 승급 제안(대표 결정). 사원 → 주임: 3회차 연속 60% 이상 |
| 게시 시간표 | 블로그 화 09:00, Threads 월·수·금 12:00, LinkedIn 화·목·토 08:30 (회차 시작 주 기준) |
| 블로그 게시 대상 | 연결된 Ghost 또는 WordPress 중 설정에서 고른 하나 |
| 게시 확인 단위 | 게시물별(결정 31 기본값) |
| 주간 분량 | 블로그 1 + 뉴스레터 초안 1 + SNS 6(Threads 3, LinkedIn 3) |

## 4. 기술 선택
- 백엔드: 기존 기본 시스템 확장(Node 24, TypeScript 바로 실행, `node:sqlite`). 스키마는 버전 번호로 이전한다(`PRAGMA user_version`).
- 화면: Preact + htm(빌드 없음, ES 모듈). `node_modules`의 두 패키지만 `/vendor`로 제공한다.
- 비밀값: 연결 토큰은 AES-256-GCM으로 암호화해 DB에 저장한다. 키는 `data/secret.key`(권한 600) 또는 `AO_SECRET_KEY`.
- AI: 공급자 인터페이스에 `complete(목적, 입력, 형식)`을 더해 업무 실행과 채용 대화(면접·회의·샘플)·학습(규칙 정리)을 같은 경로로 부른다.
- 검증: `node:test`. 가짜 AI와 로컬 스텁 서버로 연동 요청 형식을 확인한다. 실제 외부 호출은 사용자 테스트에서 한다.

## 5. 단계
| 단계 | 내용 | 완료 기준 |
| --- | --- | --- |
| P1 기반 | 스키마 이전, AI `complete`, 비동기 AI 요청, 비밀값 암호화, Preact 셸(5메뉴·라우팅·실시간), 테스트 틀 | 셸에서 기존 흐름이 동작, 테스트 통과 |
| P2 채용(S3) | 면접 후보 생성, 다듬기·계약, 기획 회의(질문→브리프), 채용 로드맵, 후보 샘플 | 빈 상태에서 매니저 → 리서처 채용까지 |
| P3 사무실(S1)·복귀(S6) | A 계열 SVG 사무실, 이벤트 기반 상태·말풍선, 하단 7단계 도크, 직원 카드(지금/대화/결과물/배운 것), DM, 복귀 요약·리플레이 | 회차 진행이 사무실·카드·기록에서 같게 보임 |
| P4 콘텐츠·결정함(S5·S2) | 결과물 구조화(게시물 단위), 게시 시간표, 결정함 작업대(플랫폼 미리보기·문단 코멘트·이번만/앞으로도), 캘린더, 회차 띠·보드·장부·상세, 모바일 | 한 회차를 결정함에서 끝까지 처리 |
| P5 연동 | 연결 7종 + 이미지, 저장(자동)·게시(예약 실행·확인 필요), 재연결 결정 요청, 알림 | 스텁 서버로 저장·게시·불명확 처리 확인 |
| P6 학습·성장(S4·S8) | 배운 것 규칙·적용, 회사 지식 승격, 숙련도·마일스톤·승급 제안, 직원 시트, 책장·트로피·연대기 | 피드백 → 다음 회차 프롬프트 반영 |
| P7 설정(S7)·운영 | 시설 6종 화면, 게시 확인 정책, 알림 정책, 실행 환경·잠금, 소유자 비밀번호, 데이터 내보내기 | 설정만으로 연결·정책 관리 |
| P8 마무리 | 전체 흐름 점검, 문서(사용 안내·구조), 남은 과제 정리 | 문서와 실제가 일치 |

각 단계는 구현 → 가짜 AI 확인 → 문서 → 커밋 순서로 끝낸다.
